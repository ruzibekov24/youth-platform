# Roadmap

Roadmap построен по принципу product-first, technology-second.

## Phase 0 — Foundation
**Цель:** понять проблему.

- определить первый user segment;
- провести интервью;
- изучить текущие workflows;
- изучить альтернативы;
- проверить core problem hypothesis;
- уточнить vision.

**Результат:** validated problem definition.

## Phase 1 — Concept
**Цель:** определить систему.

- youth journey;
- core objects;
- роль MIYA;
- ecosystem model;
- trust и safety;
- первый полезный experience.

**Результат:** product specification.

## Phase 2 — Manual MVP
**Цель:** проверить ценность без большой разработки.

Возможные эксперименты:
- ручной opportunity feed;
- community-based matching;
- ручной team matching;
- MIYA challenge;
- project showcase;
- guided youth journey.

**Результат:** доказательства реального спроса.

## Phase 3 — First Product
Только после Phase 0–2:
- выбрать платформу;
- определить architecture;
- создать минимально полезный product;
- привлечь небольшую группу;
- измерять outcomes;
- улучшать.

## Phase 4 — Ecosystem
Возможное расширение:
- advanced opportunity discovery;
- team matching;
- mentor network;
- project workspace;
- verified achievements;
- AI assistance;
- organization partnerships;
- events и challenges.

## Phase 5 — Network

**Young people ↔ Projects ↔ Organizations ↔ Mentors ↔ Opportunities**

На этом этапе платформа потенциально может стать инфраструктурой, а не просто приложением.

## Правило

Не перескакиваем из Phase 0 в Phase 3 только потому, что разработка кажется интереснее исследования.
